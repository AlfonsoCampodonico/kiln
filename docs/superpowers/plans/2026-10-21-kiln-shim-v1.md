# kiln-shim v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `containerd-shim-kiln-v1` runs a Kubernetes pod's container as a kiln microVM that owns the pod IP, with logs, exit status and stop semantics as runc gives them.

**Architecture:**
- A new crate, `crates/kiln-shim`, serves the containerd shim v2 Task API through the `containerd-shim` crate (sync).
- Pure modules translate the OCI spec, the rootfs mounts and the pod netns into kiln terms.
- A state machine over a `Backend` trait owns the task lifecycle.
- On Linux the backend spawns two kinds of process, both the same binary re-executed:
  - a root `pause` process in the pod netns;
  - one `vm` worker per container, which drops to the kiln user and boots the VM with kiln-run's building blocks and vmkit's new `TapAttach` mode.

**Tech Stack:**
- Rust 2024 (workspace edition);
- `containerd-shim` 0.11 (no features);
- serde / serde_json / toml;
- rustix;
- kiln-run, kiln-proto, kiln-image;
- vmkit (git, with `TapAttach`).

**Spec:** `docs/superpowers/specs/2026-10-21-kiln-shim-v1-design.md` (and the 2026-10-05 shim spec it implements).

## Global Constraints

- **Runtime id:** `io.containerd.kiln.v1`; the binary is `containerd-shim-kiln-v1`.
- **The shim and the `pause` process run as root. The VMM never does:** workers drop to the configured `user` before calling kiln-run or vmkit.
- **Tap:** named `kiln0`, owned by the kiln user's uid and gid, with the guest MAC equal to the pod interface's MAC.
- **One VM per pod at a time:** `Create` of a container task while another container task of the pod is created or running → `FailedPrecondition` "kiln runs one container per pod at a time".
- **Worker gone without `exited`:** the task's exit status is 255.
- **`Exec`:** `Unimplemented`, "kiln: exec needs kiln-init exec support (kiln-shim spec §4.1)".
- **RuntimeInfo annotation:** `containerd.io/runtime-allow-mounts` = `mkdir/*,format/*,erofs`.
- **Worker protocol:** JSON lines on fd 3, each line ≤ 64 KiB.
- **Config search order:** the `CreateTaskRequest.options` config path or body, then `$KILN_SHIM_CONFIG`, then `/etc/kiln/shim.toml`. Default memory is 1024 MiB.
- **Lint and test:** `cargo clippy --all-targets -- -D warnings` and `cargo test -p kiln-shim` pass on macOS and Linux. vmkit's own `cargo test` passes on Linux.
- **Style:** the code follows the repo's comment and naming style:
  - `//!` module headers that cite the spec section;
  - `thiserror` errors in libraries;
  - `#![forbid(unsafe_code)]` except where the Linux worker must use `unsafe` (`pre_exec` is avoided; rustix's safe `setns`, `unshare` and `setuid` wrappers are used instead).

## Review Focus

1. A CRI spec whose `hostname` is not a valid kiln hostname (e.g. 70 characters, or `under_score`) is replaced by `kiln-<first 12 of task id>`, not refused. Test in Task 5.
2. A rootfs from the overlayfs snapshotter (`type: overlay` with host `lowerdir`) is refused with the message naming `snapshotter = "erofs"`, not booted with no layers. Test in Task 6.
3. A pod netns whose interface has a `/32` address with a link-local gateway (Calico: `169.254.1.1`) attaches. The gateway is recorded, and the guest route is on-link (kiln-init). Tests in Tasks 2 and 7.
4. `Kill(SIGKILL)` on a task that was created but never started ends it with exit status 137, and `Wait` returns. Test in Task 9.
5. `Delete` of a running task is refused, and `Shutdown` with tasks left does not exit the shim. Test in Task 9.
