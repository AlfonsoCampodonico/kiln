# Guest IPv6 egress Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give kiln guests IPv6 egress under the same default-deny policy as IPv4: an IPv6 deny list, anti-spoofing on the tap, and neighbour discovery handled in the VM's namespace.

**Architecture:** see `docs/superpowers/specs/2026-10-21-guest-ipv6.md` (decisions D1–D9). The work is in two repositories:

- **vmkit:** `net.rs` (the dual-stack `Cidr`, the IPv6 sets and rules, pasta options, the host's IPv6 prefixes); `vmkit-sandbox` `setup_net` (the tap's IPv6 address, sysctls, the permanent neighbour entry); the test guest, the fixture and the hostile-guest suite.
- **kiln:** `Config.network.ipv6` (`kiln-proto`), `kiln-init` stage 5, the boot test, the docs and the vmkit pin.

**Tech stack:** Rust 2024, nftables (`table inet`), pasta, rtnetlink. Tests that boot VMs run in the Lima VM `vmkit` (Ubuntu 26.04, KVM, Firecracker, Cloud Hypervisor, pasta, nft).
